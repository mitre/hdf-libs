## Schema

XCCDF 1.2 has an XSD and it is vendored at `hdf-to-xccdf/schemas/xccdf_1.2.xsd` (with the CPE and `xml.xsd` schemas it imports; see that directory's `provenance.json`); libxml2 compiles it in the hdf-to-xccdf tests. It is not copied here. The ARF 1.1 XSD for `arf-minimal.xml` (NIST, `asset-reporting-format_1.1.0.xsd`) is vendored here and recorded in `provenance.json`; it imports the asset-identification and reporting-core schemas by relative path, which are not vendored, so it is hash-checked but not compiled.

`CIS_Google_Chrome_Benchmark_v2.1.0-xccdf.xml` validates against that
vendored `xccdf_1.2.xsd` (`xmllint --nonet --schema`, libxml2 2.9.13,
2026-10-28), both the full source file and the trimmed fixture.

The three DISA fixtures (`U_Multifunction_Device_and_Network_Printers_STIG_V2R15_Manual-xccdf.xml`,
`U_RHEL_9_STIG_V2R9_Manual-xccdf.xml`, `U_SLES_V11_for_System_z_STIG_V1R12_Manual-xccdf.xml`)
are XCCDF 1.1. The standalone NIST `xccdf-1.1.4.xsd` vendored at
`hdf-to-xccdf/schemas/xccdf-1.1.4.xsd` does not compile offline: it imports
`xml.xsd` and Dublin Core by URL and `cpe-language_2.1.xsd` by server-root
path. NIST's complete schema bundle for the same release,
https://csrc.nist.gov/schema/xccdf/1.1.4/xccdf-1.1.4-schema-bundle-20071011.zip
(SHA-256 as retrieved 2026-10-28
`9fa7bcbac4fef7e288d26073c59fa9bce44a681d7a02f56a48a3da17327c38c7`), carries
the companions, and its `xccdf-1.1.4.xsd` differs from the standalone file only
in those three `schemaLocation` values, which name the bundled files. Validated
against the bundle (`xmllint --nonet --schema`, libxml2 2.9.13, 2026-10-28;
the bundle is not vendored here):

- `U_RHEL_9_STIG_V2R9_Manual-xccdf.xml` validates, as does the full DISA source.
- `U_SLES_V11_for_System_z_STIG_V1R12_Manual-xccdf.xml` validates, as does the

  it into two requirements with the same id.
