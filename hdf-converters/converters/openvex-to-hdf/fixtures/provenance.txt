# OpenVEX fixture provenance

## Inputs

- **`input/spring-boot-log4j.openvex.json`** — verbatim from
  https://github.com/openvex/spec/blob/main/OPENVEX-SPEC.md "Complete
  example" section. Real-world publisher (Spring Builds bot, log4j VEX
  during the active CVE-2021-44228 disclosure).

- **`input/multi-status.openvex.json`** — synthesized to exercise every
  import path (`not_affected`, `fixed`, `affected`, `under_investigation`).
  Validated against `openvex_json_schema.json` (the official
  spec-repository schema, vendored below).

## Spec schema

`openvex_json_schema.json` is a verbatim copy of
https://github.com/openvex/spec/blob/main/openvex_json_schema.json — the
authoritative JSON Schema for OpenVEX 0.2.0. Stored here so fixture
validity can be re-checked in CI without a network round-trip.

To re-validate every fixture:

```bash
cd /tmp && pnpm add -s -D ajv ajv-formats
node - <<'EOF'
import Ajv from 'ajv/dist/2020.js';
import addFormats from 'ajv-formats';
import { readFileSync } from 'node:fs';
const ajv = new Ajv({ allErrors: true, strict: false });
addFormats.default(ajv);
const schema = JSON.parse(readFileSync('hdf-converters/converters/openvex-to-hdf/fixtures/openvex_json_schema.json', 'utf-8'));
const validate = ajv.compile(schema);
for (const f of ['spring-boot-log4j.openvex.json', 'multi-status.openvex.json']) {
  const p = `hdf-converters/converters/openvex-to-hdf/fixtures/input/${f}`;
  console.log(f, validate(JSON.parse(readFileSync(p, 'utf-8'))) ? 'VALID' : validate.errors);
}
EOF
```

## Expected

`expected/*.json` are regenerated by the CLI on every run — they record
the round-trip HDF Amendments output for visual diff review. They do not
gate the test suite; the in-memory Go and TypeScript tests are
authoritative.
