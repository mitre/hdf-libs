# nexusiq-to-hdf fixtures — provenance

Recorded 2026-10-21. No Nexus IQ (Sonatype Lifecycle) policy-evaluation result
exists in mitre/heimdall2 or mitre/saf, and neither has a converter for it.

## `input/`

### `policy-evaluation.json`
Real output: the result file the Nexus IQ CLI writes with `--result-file`,
attached to mitre/hdf-libs issue #482 as `sample-nexusiq-result.json`
(https://github.com/user-attachments/files/33770252/sample-nexusiq-result.json),
retrieved 2026-10-21. Byte-identical to the attachment: sha256
565e7f73ccf7ad5b12076f4ba975cd4618afea5b648a938a2a5699578071b3dc. Not trimmed;
all 15 alerts across the four policies are kept.

Redacted by the contributor before attachment, identifying data only. The
values before redaction identify the contributor's organization, so they were
not shared and are not recorded here, not even their shape:
- `applicationId`, and the same value inside the four report URLs — replaced
  with `example-org_example-app_dev`.
- `scanId`, and the same value inside the four report URLs — replaced with
  `0a1b2c3d4e5f60718293a4b5c6d7e8f9`.
- The IQ server host in `reportHtmlUrl`, `reportPdfUrl`, `reportDataUrl` and
  `prioritiesUrl` — replaced with `lifecycle.example.com`.
- `componentFacts[].pathnames` — the source-tree paths replaced with
  `./app/module-a.zip`, `./app/module-b.zip` and `./app/module-c.zip`, which
  the contributor confirms is the right sanitized form.
- `componentFacts[].hash`, `policyId`, `constraintId` and `policyViolationId`
  — every value replaced, because the IQ originals are identifying. As
  attached they are lowercase hex, 20 characters for a hash and 32 for an id,
  and no assertion here pins them to anything IQ issued.
Kept as IQ reported it, per issue #482: the public data — CVE ids, package
names and versions.

Coverage this fixture cannot give: it has never been compared against an
unredacted result, and it carries no SAST alert. Validation against a live
Nexus IQ Server is left to someone with access to one.

The public data was checked against its sources on 2026-10-21: the five CVEs
(CVE-2026-97687, -97688, -97689 against urllib3 2.7.0; CVE-2026-85999, -86000
against soupsieve 2.8.4) resolve in OSV and NVD, with the GHSA and PYSEC
aliases OSV lists for those package versions, and urllib3 2.7.0, soupsieve 2.8.4
and defusedxml 0.7.1 are published on PyPI. The summary counters reconcile with
the alerts under Sonatype's threat-level bands: 7 critical (8-10), 6 severe
(4-7), 2 moderate (2-3).

## Tool and version, read from the file itself (2026-10-21)

A version below is what the fixture *says about itself*; where a format carries
no producer version, that is stated rather than guessed.

- `policy-evaluation.json` — Nexus IQ CLI policy-evaluation result; the format
  carries no IQ server or CLI version, so the version is not determinable from
  file content. It also carries no evaluation time.
- `empty.json` and `maven-policy-evaluation.json` — no producer version or
  evaluation time is present in either published file.
- `scan-history-summary.json` — the evaluationDate is present, but no producer
  version is identified. This input is rejected rather than converted.

## Schema

Sonatype publishes no schema for the CLI result file. Searched 2026-10-21: the
Nexus IQ CLI documentation describes `--result-file` only as machine-readable
JSON, and the Policy Violation REST API documents a related but different shape
(`constraintViolations` rather than `componentFacts`).
The published scan-result and REST documentation were checked again on
2026-11-05. The new fixtures are published examples, not schema-confirmed
synthetic reports. Live validation against an unredacted IQ instance and a real
SAST sample remain outstanding on the original feature card.
