### `../source-rule-url-cases.json`
Schema-confirmed adaptations, NOT real scanner output. Each input starts from
`source-rule-urls.json`, retains only the first unsafe finding and the version,
results, errors and paths members, and replaces that finding's metadata to cover
independent keys, distinct/duplicate URLs, absent/empty/redacted values, wrong
JSON types, unrecognized key punctuation, case variants before/after canonical names and
case-variant-only metadata across mapped fields. The duplicate-exact-key case
contains two source_rule_url members in its JSON text, with the last value expected. Three additional cases add uppercase RESULTS, EXTRA
or METADATA alongside the canonical envelope fields to ensure they cannot replace
the metadata before conversion; two more add uppercase LINE/SCANNED to check
source-position and scan-coverage preservation. `name` and `urls` are test-vector
annotations, not Semgrep fields. Both languages consume these same inputs.

## Schema

Semgrep publishes the JSON Schema for `--json` output in semgrep/semgrep-interfaces, tagged per release. The fixtures report `version` 1.174.0, so that tag's `semgrep_output_v1.jsonschema` is vendored here as `semgrep_output_v1-1.174.0.schema.json` and recorded in `provenance.json`.

Validation (ajv, 2026-09-20): all four inputs validate. The schema is JSON Schema 2020-12 and encodes error types as tuples (`prefixItems`), which gojsonschema does not implement — it reports `errors.json` as failing the `oneOf`, an engine artifact, not a defect in the file; ajv is the engine of record for this schema.

The 1.183.0 output schema is vendored as `semgrep_output_v1-1.183.0.schema.json`
and recorded in provenance.json. The TypeScript converter tests validate the
real capture and every adapted case with Ajv2020 through the shared schema
validator; metadata is raw JSON in the official schema. Validation passed for the
real capture and all 35 adapted cases on 2026-11-09 (Ajv2020).
