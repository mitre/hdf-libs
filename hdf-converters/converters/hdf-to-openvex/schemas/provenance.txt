# OpenVEX JSON Schema — provenance

`openvex_json_schema.json` is the OpenVEX specification repository's own JSON
Schema. It gates `hdf-to-openvex` output in both languages, and the reverse
importer `openvex-to-hdf` records its input fixtures as validated against the
same copy (see `../../openvex-to-hdf/fixtures/provenance.txt`). The converter emits
`"@context": "https://openvex.dev/ns/v0.2.0"`, which this schema matches: its
own `$id` is `openvex_json_schema_0.2.0.json`.

## Why a commit pin and not the v0.2.0 tag

**No tag in `openvex/spec` contains this file.** The repository has exactly two
tags, `v0.0.2` and `v0.2.0`; `v0.2.0` points at commit `7667061` (2023-08-22) and
its tree holds only `OPENVEX-SPEC.md`, the governance documents and the README.
The schema was first committed on 2024-03-15 ("feat: json schema for version
0.2.0"), months after the tag, and has been amended six times since. The
spec-0.2.0 conformance target therefore exists only on `main`, and the strongest
available pin is the commit that last changed the blob — which is what the
`source` URL above resolves.

`pinned_ref` is recorded as an explicit field here rather than left implicit in
the URL, because a 40-character commit SHA inside a raw.githubusercontent path
is not self-evidently a pin the way `/releases/download/v1.2.3/` is.
