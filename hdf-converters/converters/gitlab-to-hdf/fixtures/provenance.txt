## Schema

GitLab publishes a JSON Schema per report type and version (gitlab-org/security-products/security-report-schemas, `dist/<type>-report-format.json` at tag `v<version>`). The fixtures declare `version` 15.1.0 with `scan.type` sast (three) and dast (one), so `sast-report-format-15.1.0.json` and `dast-report-format-15.1.0.json` are vendored here and recorded in `provenance.json`.

Validation (gojsonschema, 2026-09-20): all four inputs validate, and `go/schema_validation_test.go` keeps it that way. They did not when the schemas were first vendored earlier the same day — every one lacked the required `scan.scanner.vendor` and `scan.analyzer.vendor`, `minimal-dast.json` lacked `scan.scanned_resources`, and `multi-vuln.json`'s third vulnerability had an empty `identifiers` array where the schema requires one. The fixtures were amended with the values a real GitLab run carries (scanner vendor Semgrep or OWASP, analyzer vendor GitLab, the DAST scanned resource taken from the finding's own location, a `semgrep_id` identifier for the third vulnerability); the goldens changed only by the input checksum and by the identifier the third vulnerability now carries. The empty-identifiers case the old fixture exercised moved to inline-JSON unit tests in both languages.
