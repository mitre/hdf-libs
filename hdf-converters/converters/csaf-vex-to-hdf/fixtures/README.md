# CSAF VEX fixture provenance

## Inputs

All five inputs are **verbatim copies** of the official OASIS CSAF spec
repository's `csaf_2.0/examples/csaf/csaf_vex/` directory:
https://github.com/oasis-tcs/csaf/tree/master/csaf_2.0/examples/csaf/csaf_vex

- `2022-evd-uc-01-na-001.json` — Use Case 1, "Not Affected" status.
  Produces one `falsePositive` override.
- `2022-evd-uc-01-f-001.json` — Use Case 1, "Fixed" status. Produces one
  POA&M override pinned to `failed` pending re-scan.
- `2022-evd-uc-01-a-001.json` — Use Case 1, "Affected" status. Produces
  no override (informational); exercises the empty-actionable-statements
  error path.
- `2022-evd-uc-01-ui-001.json` — Use Case 1, "Under Investigation"
  status. Also produces no override; same error path.
- `sec-vex-2022-0001.json` — Secvisogram's own VEX statement asserting
  no exposure to Log4Shell. Three CVEs, each with `flags[]` carrying
  `component_not_present` — exercises the flag-derived justification path.

## Spec schema

`csaf_json_schema.json` is a verbatim copy of
https://github.com/oasis-tcs/csaf/blob/master/csaf_2.0/json_schema/csaf_json_schema.json
— the authoritative CSAF 2.0 JSON Schema. Stored here so fixture
provenance can be re-checked offline.

**Note:** the CSAF schema references CVSS sub-schemas
(`https://www.first.org/cvss/cvss-v3.1.json` etc.) that use JSON Schema
draft-04. Ajv 2020 cannot resolve these without an extra Ajv-draft-04
shim. Since the fixtures here are verbatim spec-repo examples (route #1
"documented provenance" per `build-converter.md` Step 2), schema
re-validation is not required to demonstrate fixture integrity.

If schema-validation is needed: use the official OASIS CSAF Python
validator (`csaf-validator`) which handles the mixed-draft references
natively.

## Expected

`expected/*.json` are regenerated by the CLI on every run — they record
the round-trip HDF Amendments output for visual diff review. They do not
gate the test suite; the in-memory Go and TypeScript tests are
authoritative.
